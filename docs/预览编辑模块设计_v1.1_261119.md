# MD Preview 预览编辑模块设计

版本：v1.1；日期：2026-11-19；适用 v1.9.8。替代 v1.0 的受限纯文字方案。

## 需求与选型

真实方案大量使用标题、粗体、链接、列表和表格。原来的普通顶层段落筛选无法满足预览编辑，因此采用固定 Vditor 4.0.1 WYSIWYG 编辑模型，覆盖完整标准文字结构。保持原有 Rust + 系统 WebView 单项目、单 EXE；不引入服务器或 Node 运行时。

依赖来自官方 npm 包，tarball SHA-512 与 npm 元数据一致；选用的 12 份资源由 `assets/editor/manifest.json` 锁定 SHA-256。Vditor、Lute 和 KaTeX 许可证随资源及发布包保留。参考：[官方仓库](https://github.com/Vanessa219/vditor)。

## 模块与数据

| 模块 | 职责 |
| --- | --- |
| `src/editor_assets.rs` | 严格白名单的内嵌 JS/CSS 资源响应、进入编辑前原文备份 |
| `assets/enhance/preview-edit.js` | Vditor 生命周期、结构化 DOM 序列化、输入/组合输入、光标、图片显示映射 |
| `src/main.rs` | 既有源码状态、自动保存、脏标记、只读恢复、标签、搜索及打印协调 |
| `assets/enhance/preview-enhance.js` | 普通预览增强，以及两种模式共用的图表灯箱与下载 |

原始 Markdown → 原文备份 → 延迟加载编辑器 → 结构化编辑 → 同一隐藏源码状态 → 既有保存 IPC → 原文件。普通阅读仍由 pulldown-cmark 渲染；只有点击编辑按钮才加载约 4 MB 的编辑器资源。

原始源码和分屏入口保留；切换模式会结束结构化编辑并同步最新内容。进入前创建备份，失败时不进入编辑；仅打开但未修改时保持原文。YAML 元数据独立展示并原样拼回。编辑后列表符号、空白、表格排版等可规范化，CRLF 沿用 textarea 的 LF 规范化行为，撤销栈不跨模式和标签保留。

## 保存与状态

DOM 输入立即标记脏状态，短延迟序列化后复用约 700 ms 自动保存。Ctrl+S、标签切换、关闭等先同步当前 DOM，避免仅等待编辑器延迟回调。保存确认和外部变更判断也先同步尚未提交的 DOM；旧版本保存确认不能把新输入标成已保存。中文组合输入暂停序列化和自动保存，完成后保存；原有只读文件另存为/放弃/取消流程继续工作。

原文件精确字节备份位于配置目录 `backups/`，以时间、路径哈希和原文件名区分，不覆盖已有备份。当前每次进入结构化编辑创建一个备份，不自动清理。

加粗、斜体和删除线动作执行前，按当前选择区同步按钮状态，避免 Vditor 延迟更新的工具栏高亮把快速跨块操作反向执行。

## 图片与图表

普通预览图片附带原始引用元数据，编辑器用受控本地协议显示；序列化前在 DOM 副本中恢复原路径。保存后更新显示映射，连续保存不使图片注册过期；更换文档清空映射，防止相同相对路径串图。

Mermaid 的源码保留在编辑模型中，预览面板显示图形。点击图形直接调用共用灯箱，不触发代码展开；放大、空格拖动、SVG 和 3× PNG 下载共用既有代码。图形节点拖拽或直接修改图中标签不属于本版本；需要改 Mermaid 时使用代码块编辑或源码模式。

## 搜索与导出

编辑器加载复用的 Mermaid 时强制保留 `securityLevel=strict`，不采用上游默认的宽松初始化。

结构化编辑使用 Range + CSS Highlight 搜索，不插入 mark 标签污染编辑模型，不退出编辑模式。原有 Ctrl+H 保持源码替换行为。打印/PDF 先同步最新 Markdown，再请求 Rust 生成当前预览，等待 Mermaid 渲染完成后导出，避免使用隐藏的旧预览。DOCX 从同一最新 Markdown 导出。

## 验收与回滚

浏览器验证按需/离线加载、备份失败、标题/富文本/列表/表格、保存确认、搜索和窄窗口；Windows 原生测试以夹具及两份真实方案副本验证实际写盘、原文备份、原图路径、公式、撤销重做、组合输入、快速切换、重复保存和 SVG/PNG 文件。仅操作副本，不修改业务原件或文件关联。

尚需人工验证真实中文输入法和其他系统原生 WebView；自定义 HTML 在编辑器中可作为源码块呈现，不承诺所有扩展语法视觉一致。回滚只需关闭 v1.9.8 启动保留的旧 EXE；若需要撤回文档修改，从对应 `.bak` 恢复，先保留当前文件，不删除配置、图片或备份。
